# Project memory and documentation

Read [live_project_delivery_register.md](live_project_delivery_register.md) before starting any work in this repository. It is the persistent project memory and authoritative delivery-status register.

**Anything and everything relevant to this project must be documented in the register, or linked from it with a clear summary.** Record requirements, user clarifications, decisions and rationale, assumptions, changes, bugs and severity, risks, blockers, experiments, test outcomes, releases and next actions. Update it during material changes and before handing work back to the user.

Use stable IDs, dates, statuses, owners, source evidence and acceptance criteria. Preserve history and explain superseded decisions. Distinguish observed results from static analysis and unverified hypotheses. Never mark a fix verified without recording validation. Never put secrets, API keys or private document/transcript content in project memory.

Follow the full documentation policy and current handoff priorities in the register. Update supporting documentation when behavior changes and link it from the register.
